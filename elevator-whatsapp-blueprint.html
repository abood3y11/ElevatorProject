02

حل مشكلة الصور والملصقات (خط معالجة الوسائط)

السبب الجذري: واتساب لا يرسل الملف نفسه في الـ Webhook، بل يرسل معرّفاً media_id يجب تنزيله خلال مهلة محددة.

⚠️ لماذا لا تظهر الوسائط عندك الآن؟ الـ Webhook يصلك فيه type: "image" و image.id فقط بدون رابط مباشر. إن لم تنفّذ خطوة التنزيل والتخزين، لن يكون لديك ملف لعرضه — وهذا ما يحدث في نظامك.
خط معالجة الوسائط الصحيح — Media Pipeline
sequenceDiagram
  autonumber
  participant C as 🙋 العميل
  participant M as Meta Cloud API
  participant S as خادمك (Webhook)
  participant ST as التخزين S3/MinIO
  participant UI as واجهة الموظف
  C->>M: يرسل صورة العطل 📷
  M->>S: Webhook { type:"image", image:{ id, mime_type, sha256 } }
  S->>M: GET /v19.0/{media_id} (Bearer Token)
  M-->>S: { url: "رابط مؤقت صالح ~5 دقائق" }
  S->>M: GET url مع نفس الـ Token
  M-->>S: بايتات الملف الفعلية
  S->>ST: حفظ الملف + توليد Thumbnail
  S->>S: تخزين السجل: message(type, mime, storage_url)
  UI->>ST: عرض الصورة عبر رابط موقّع Signed URL

قاعدة 1 التنزيل الفوري

  • رابط الوسائط من Meta مؤقت (~5 دقائق) — نزّل فور وصول الـ Webhook
  • استخدم طابور Queue حتى لا يتأخر الرد على Meta (يجب إرجاع 200 خلال ثوانٍ)
  • أعد المحاولة Retry عند الفشل (3 محاولات + Backoff)

قاعدة 2 العرض حسب النوع

  • image (jpeg/png) ← معاينة + تكبير Lightbox
  • sticker ← ملف webp يُعرض كصورة 128px شفافة
  • audio/voice ← ogg/opus: مشغّل صوت (حوّل إلى mp3 إن لزم للمتصفحات القديمة)
  • video ← مشغّل مع Poster frame
  • document ← بطاقة باسم الملف + أيقونة النوع + زر تنزيل
  • location ← خريطة مصغّرة بإحداثيات المبنى 📍

قاعدة 3 نوع غير مدعوم؟

  • لا تُسقط الرسالة أبداً — اعرض بطاقة: "📎 مرفق من نوع X"
  • خزّن الـ payload الخام دائماً للرجوع إليه
  • وسائط العميل مفيدة جداً هنا: صورة لوحة العطل أو رقم المصعد تسرّع التشخيص!

04

الأقسام والأدوار داخل النظام

هيكلك التنظيمي مُسقطاً على المنصة: كل قسم = صندوق وارد + فريق + صلاحيات.

📞

المبيعات والتعاقدات

  • مدير المبيعات: عروض الأسعار، تجديد العقود، كبار العملاء
  • مسؤول العقود: بنود العقود، الامتثال لـ SLA، الجوانب الإدارية
  • يستقبل: عقود جديدة، تحديث مصاعد، عروض أسعار، تجديدات
🔧

العمليات الفنية

  • مدير العمليات: يراقب كل الأقسام الفنية والمؤشرات
  • مشرف الصيانة: يستقبل البلاغات، يفتح التذاكر، يوزع الفنيين
  • فني الصيانة: تطبيق جوال — يستلم التذكرة وينفذ ويوثق
  • مدير التركيب + مراقب الجودة: متابعة مشاريع التركيب والفحوصات
  • يستقبل: أعطال، بلاغات طوارئ، مواعيد صيانة دورية
📋

التنسيق والدعم

  • منسق العمليات: جدولة الفنيين، تنسيق دخول المواقع، حلقة الوصل
  • يستقبل: تأكيد مواعيد، تنسيق دخول، متابعة حالة زيارة
💬

علاقات العملاء

  • مسؤول علاقات: الشكاوى، الاستفسارات الإدارية، الفواتير والعقود القديمة
  • مسؤول الحسابات المالية: المستحقات، تذكيرات السداد، الفواتير
📦

المخزون والمشتريات

  • أمين المخزون: استفسارات توفر قطع الغيار، طلبات الفنيين للقطع
  • يستقبل: طلبات قطع من التذاكر، استفسارات توفر وأسعار
💼

الإدارة العليا

  • رئيس قطاع المصاعد: لوحة مؤشرات فقط + تنبيهات الطوارئ والتصعيد
  • لا يستقبل محادثات — يراقب SLA والربحية والالتزام

🚨 قاعدة ذهبية للمصاعد: الطوارئ تتجاوز كل شيء كلمات مثل "محتجز، عالق، أشخاص داخل المصعد، باب لا يفتح" تتجاوز البوت والقائمة وساعات الدوام تماماً: تذكرة أولوية P1، إشعار صوتي للمشرف المناوب، وإسناد فوري لأقرب فني — مع مؤقّت SLA ظاهر بالدقائق. سلامة الأرواح لا تنتظر "اضغط 1".

طبقة 1 قائمة البوت التفاعلية

  • رسالة ترحيب بأزرار واتساب (List Message حتى 10 خيارات)
  • تُرسل لأول رسالة أو بعد 24 ساعة صمت
  • لكل خيار: سؤال متابعة لجمع البيانات قبل التحويل

طبقة 2 الكلمات المفتاحية

  • قاموس قابل للتعديل من الإعدادات لكل قسم
  • أمثلة: "عطل، واقف، صوت غريب، رجّة" ← صيانة
  • "عرض سعر، عقد، تركيب جديد" ← مبيعات
  • "فاتورة، سداد، شكوى" ← علاقات عملاء

طبقة 3 التوزيع داخل القسم

  • Round-Robin أو أقل موظف حِملاً
  • مراعاة حالة الموظف (متاح/مشغول)
  • المشرف يعيد التوزيع يدوياً في أي لحظة
  • غير المسند خلال X دقائق ← تنبيه للمشرف
06

حالات الاستخدام لكل قسم

ما يفعله كل قسم داخل النظام — مرقّمة وجاهزة كمتطلبات Requirements.

مبيعات UC-S

  • UC-S1 استقبال طلب عرض سعر وفتح فرصة Lead
  • UC-S2 إرسال عرض PDF داخل المحادثة ومتابعة قراءته
  • UC-S3 تنبيه آلي قبل انتهاء العقد بـ 60/30 يوماً + رسالة تجديد بقالب معتمد
  • UC-S4 تحويل العميل بعد التوقيع إلى التنسيق لجدولة أول زيارة
  • UC-S5 وسم العملاء المحتملين ومتابعة Pipeline

صيانة UC-M

  • UC-M1 استقبال بلاغ عطل مع صور/فيديو/صوت العطل
  • UC-M2 فتح تذكرة من المحادثة بضغطة: تُملأ تلقائياً (العميل، المبنى، المصعد، الوصف، المرفقات)
  • UC-M3 إسناد التذكرة لفني وإرسال تفاصيلها لتطبيقه
  • UC-M4 تحديثات آلية للعميل: "الفني في الطريق 🚗" / "تم الإصلاح ✅"
  • UC-M5 مسار الطوارئ P1 (احتجاز) بتصعيد فوري
  • UC-M6 جدولة الصيانة الوقائية الشهرية وإشعار العميل بالموعد
  • UC-M7 توثيق الفني: صور قبل/بعد + توقيع العميل + تقرير
  • UC-M8 كشف الأعطال المتكررة لنفس المصعد وتنبيه الجودة

تنسيق UC-C

  • UC-C1 تأكيد مواعيد الزيارات مع العميل عبر أزرار (تأكيد/تأجيل)
  • UC-C2 تنسيق تصاريح دخول المواقع والأبراج
  • UC-C3 توزيع الرسائل غير المصنفة على الأقسام
  • UC-C4 متابعة وصول قطع الغيار المطلوبة للتذاكر
  • UC-C5 جدول الفنيين اليومي وإعادة الترتيب عند الطوارئ

علاقات عملاء ومالية UC-R

  • UC-R1 استقبال الشكاوى وفتح ملف شكوى بمهلة معالجة
  • UC-R2 إرسال الفواتير وتذكيرات السداد بقوالب آلية
  • UC-R3 استفسارات العقود القديمة وكشوف الزيارات
  • UC-R4 استطلاع رضا CSAT بعد إغلاق كل تذكرة
  • UC-R5 تصعيد الشكاوى الحرجة لرئيس القطاع

مخزون UC-I

  • UC-I1 استقبال طلب قطعة غيار من تذكرة الفني
  • UC-I2 الرد على استفسارات التوفر والسعر
  • UC-I3 إشعار الفني والمنسق عند وصول القطعة

إدارة عليا UC-E

  • UC-E1 لوحة مؤشرات حية: زمن الاستجابة، التذاكر المفتوحة، SLA
  • UC-E2 إشعار فوري بكل حالة طوارئ P1 وتقرير إغلاقها
  • UC-E3 تقرير شهري: أعطال حسب المبنى/المصعد/النوع، تجديدات العقود

تدفقات العمل الحرجة

أهم رحلتين: بلاغ العطل العادي، وحالة الطوارئ (احتجاز).

التدفق 1 — بلاغ عطل بصورة: من الرسالة حتى التقييم
sequenceDiagram
  autonumber
  participant C as 🙋 حارس المبنى
  participant B as 🤖 البوت
  participant M as 🔧 مشرف الصيانة
  participant T as 👷 الفني (تطبيق)
  participant I as 📦 المخزون
  C->>B: "المصعد واقف" + صورة لوحة العطل 📷
  B->>B: كلمة "واقف" ← قسم الصيانة + معالجة الصورة
  B->>C: "أي مبنى؟" (أزرار بمباني العميل المسجلة)
  C->>B: يختار "برج النخيل - مصعد 2"
  B->>M: محادثة + تذكرة مسودة (المصعد، الصورة، الوصف)
  M->>T: اعتماد التذكرة وإسنادها لأقرب فني
  T->>C: تحديث آلي "الفني أحمد في الطريق 🚗 خلال 40 دقيقة"
  T->>I: يطلب قطعة (كرت تحكم) من التطبيق
  I->>T: "متوفرة — تُسلَّم مع السائق"
  T->>T: إصلاح + صور قبل/بعد + توقيع الحارس
  T->>C: "تم إصلاح المصعد ✅" + تقرير مختصر
  B->>C: "قيّم الخدمة ⭐" ← يُسجل في تقرير الفني

  E->>X: تقرير الحادثة: زمن الاستجابة الكلي

خطة الترقية المرحلية (Roadmap)

لا تبنِ كل شيء دفعة واحدة — 4 مراحل تحافظ على عمل نظامك الحالي أثناء التطوير.

المرحلة 1 إصلاح الأساس (أسبوعان)

  • بناء خط معالجة الوسائط (القسم 02) — يحل مشكلة الصور والملصقات فوراً
  • إضافة جدولي media_file و department لقاعدة البيانات
  • التأكد من استخدام WhatsApp Business API الرسمي (وليس تطبيق الهاتف) لدعم تعدد الموظفين بنفس الرقم

المرحلة 2 الأقسام والتوجيه (3-4 أسابيع)

  • صناديق وارد منفصلة بالأقسام الستة + إشعارات لكل قسم على حدة
  • بوت القائمة (1-5) + قاموس الكلمات المفتاحية + مسار الطوارئ P1 قبل أي شيء آخر
  • الإسناد داخل القسم + رد خارج أوقات الدوام

المرحلة 3 التذاكر والأصول (4-6 أسابيع)

  • سجل المباني والمصاعد والعقود + استيراد بياناتك الحالية
  • إنشاء تذكرة من المحادثة + لوحة Kanban + تطبيق/شاشة الفني
  • التحديثات الآلية للعميل وربط المخزون بطلبات القطع
  • ملصقات QR داخل الكابينات تفتح واتساب برقم المصعد جاهزاً

المرحلة 4 الذكاء والتقارير (مستمر)

  • جدولة الصيانة الوقائية الآلية من بنود العقد + تذكيرات التجديد
  • تقارير: زمن أول رد، SLA، الأعطال المتكررة لكل مصعد، أداء الفنيين، CSAT
  • لاحقاً: رد آلي بالذكاء الاصطناعي على الأسئلة الشائعة قبل التحويل
